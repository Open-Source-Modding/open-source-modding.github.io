# Watch Dogs: Legion Lua function index

Source: function-name list extracted from Watch Dogs: Legion. The extraction method for this particular list is not recorded here; it is a flat dump of global names and table members, not a generated API reference.

These are the script function names that Watch Dogs: Legion exposes to its Lua 5.1 runtime. The list is a name inventory only: there are no signatures, no argument lists, no parameter order and no return types. A name tells you that a capability exists and roughly what it is for, but it does not tell you how to call it. Everything below was taken from the name text alone, and no behaviour has been inferred.

## What the list can and cannot tell you

- What it gives: the full set of callable entry points that the shipped scripts can reach, plus the names of several engine manager tables and a handful of Lua values and userdata objects.
- What it does not give: argument shapes, types, defaults, who may call a function (client, server, or both), or which runtime state it needs.
- Consequence: you can use the list to find out whether a feature is scriptable, to find the likely function for a task, and to compare naming across versions. To actually call anything you need the argument shapes, which have to come from the game's own scripts or from a decompiler.

## How to read the names

Most names are verbs followed by a noun, and the verb prefix usually states the kind of operation:

- `Set` / `Get`: write or read a value or a state on an entity, manager or system. These are the most common prefixes by a wide margin.
- `Is` / `Are` / `Has`: ask a yes or no question. `Has` is used for possession or detection, `Are` for a set of things, `Is` for a single thing.
- `Start` / `Stop`: begin or end a running behaviour, sequence or system.
- `Enable` / `Disable`: turn a feature or handler on or off.
- `Add` / `Remove` / `Clear`: change the membership or contents of a set, list, override stack or parameter block.
- `Play` / `Stop`: run media or an animation, often paired (`PlaySound` / `StopSound`).
- `Send`: push an event, command or request to an entity or manager.
- `Register` / `Unregister`: subscribe or unsubscribe a callback or a provider.
- `Force`: override normal logic and push a system into a chosen state.
- `Modify`: change an existing value in place rather than replacing it.
- Prefixless nouns also exist, for example `CameraShakeAndGamePadRumble`, `AgentDrawWeapon` and `FelonyStartChase`, where the subsystem is the first token.

Two more conventions matter when reading the list:

- A `_v2`, `_v3`, `_v4` and so on suffix marks a reworked or replaced variant of a function. The older entry is normally kept alongside the new one, so several functions appear as a rising sequence of versions (`ReinforcementStartReinforcing` runs from the base name up to `_v6`, and `SetAIAgentState` runs up to `_v4`). A few `V2` and `V3` forms without the underscore also appear, for example `SendAICmdBHVstateV2` and `PlayBinkVideoFileWithSubtitleV3`.
- Some entries are Lua-standard names rather than Legion-specific ones (`collectgarbage`, `pcall`, `tostring`, and the members of `math`, `string`, `table`, `os`, `io`, `coroutine` and `debug`). They are in the dump because it captures the whole global environment, not only the game's own functions.

### Notation in the full list

The full list keeps every line exactly as it appears in the source, so three shapes appear:

- `Name()`: a function reachable directly as a global.
- `- Name()`: a member of a table. The leading dash comes from the dump, which lists table members under their table. The table may be a Lua standard library (`- abs()` under `math`) or an engine manager table (`- RegisterEventCallback()` under `Globals`).
- `Name [table]`, `Name [userdata]` and `Name :type: value`: non-function entries, namely the manager tables themselves (`CAIAgentManager [table]`), userdata objects (`System [userdata]`) and constant values (`pi :number: 3.141593`, `_VERSION :string: Lua 5.1`). They are part of the same inventory and are kept in the list for completeness.
